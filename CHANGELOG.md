# Changelog

## Unreleased

Not a published release. The product version stays `0.1.0` so this client still matches `agtd`.

- Interactive session: `agt` on a terminal, `agt tui`, and `agt tui --dump`. The dump is example data and does not change a repository. Approvals stay bound to the argument hash. Apply stays bound to the digest. Ctrl+C leaves the screen and does not cancel or apply.
- Ask and plan are stored on the run. The daemon denies writes, test runs, and other mutations in those modes, including a create that bypasses the session. They finish with outcome `answered` and do not run repair verification. An empty interaction stays `agent`. `risk_level` is unchanged. Migration `005_interaction.sql` adds the column.
- Assistant text can be shown while the response is read. A tool call is still returned only after the body is complete and the arguments are valid JSON. An interrupted stream that has already shown text is not retried. Reconnecting does not repeat the edit.
- Approval and apply keys act on the focused confirm line. Composer text does not approve or apply. Routine hashes and digests are abbreviated. `ctrl+f` and the apply confirmation show the full values. The cent limit is labelled an estimate. Untrusted terminal controls are stripped from rendered text. Demo scenes stay out of a live session.
- `agt setup --confirm` records a profile and a test command. It does not select an image or start a run.
- Sessions are stored apart from runs. Migration `006_sessions.sql` adds `sessions`, ordered `session_messages`, and a nullable `runs.session_id`. A standalone run still works. `agt session list|new|open|show|submit` and `/sessions` reopen a session. An active session attaches to its existing run. A finished session shows its history. Neither starts work, replays a tool, or applies a patch. A repeated client message id does not create a second message or run. A new prompt while a run is active is refused and does not change that goal. A session stays bound to its canonical repository path. A new `/fix` uses a fresh snapshot. An unapplied patch stays pending, and the note says its edits are absent from that snapshot.
- A fake-provider result and its usage row record the configured model name when one is set. The provider stays the scripted fake provider. An unset model name stays empty. The provider string is not stored as the model name.
- Named model configurations. `AGT_MODELS` lists names beyond `default`. Each name reads `AGT_MODEL_<NAME>_ADAPTER`, `ENDPOINT`, `MODEL`, `INPUT_USD_PER_M`, `OUTPUT_USD_PER_M`, `API_KEY_ENV`, and `SCRIPT`. Only the credential variable name is stored. `agt model list` and `agt model select` choose a configuration and do not call a model. `/model` stores the choice on the open session, or as the daemon default when no session is open. The status line shows that configuration and labels a fake provider `scripted`. A new run records the provider, model, endpoint, and prices. An existing run keeps the snapshot it was created with. A named OpenAI configuration with an empty endpoint is rejected and is not given `https://api.openai.com/v1`. The legacy `default` OpenAI configuration still uses that URL when `AGT_MODEL_BASE_URL` is unset. A loopback endpoint may omit a key. Any other endpoint requires the named variable. A failed call does not switch endpoints. Migration `007_models.sql` adds the columns. The product version stays `0.1.0`.
- API contract `api.v2`. Health and identity advertise capabilities `sessions` and `models`, and a local build id in `X-Agt-Build`. `make build` stamps `local+<revision>[-dirty].<utc>`. The product version stays `0.1.0`. A daemon at that product version that does not advertise the contract or those capabilities is rejected. The message names `make build` and says to restart that daemon yourself. The client does not stop the other process.
- Integration tests use a disposable database named `agt_test_` plus random hex, an isolated `AGT_DATA_DIR`, a loopback port other than `8787`, and a container namespace taken from that data directory. `make test` points `AGT_DATABASE_URL` at the `postgres` maintenance database. Tests do not reset or drop database `agt`. Reset and drop run only when the current database name and the `agt_harness` marker match the test that created them. A missing sandbox container, reported as `no such object` or `no such container` in either case, is treated as already gone.
- No base backup of database `agt` was found, and `archive_mode` is off. WAL alone cannot restore rows that were already truncated. Those historical runs and sessions were not restored. One suite-residue run and one session remain in database `agt` and were left in place. They are not a backup.
- Read-only Codex and Claude protocol fixtures. `agt agent list` shows model API configurations separately from those coding agents and does not call a model or start a CLI. `codex exec --json` fixtures use protocol `codex-exec-jsonl/1`. Claude `stream-json` fixtures use `claude-stream-json/1`. A translated read is an AGT policy decision and is not performed. Writes, tests, and host commands are denied. A subagent tool call is denied as well. Partial tool JSON is discarded. `agt agent run` is unavailable for both read-only and mutating work, because the external CLI owns its files, subprocesses, and network. Installed versions are probed with `--version` only. Credential files are not read. Parsing those fixtures is not live Codex or Claude compatibility.
- Codex app-server client. `agt agent ask` requires `--authorize-live` and posts `POST /v1/agents/codex/ask`. The route is authenticated and is not a health capability. It copies the repository into the daemon data directory and does not enqueue a run. The child environment keeps `PATH` and `HOME` so a ChatGPT subscription login can be found, and it does not receive `OPENAI_API_KEY` or `CODEX_API_KEY`. API-key billing is refused. The client speaks app-server JSON-RPC on stdio with `experimentalApi`. It passes process-local permission profile `agt-snapshot` and does not combine that profile with `sandboxPolicy`. `shell_tool` must echo false before `thread/start`. The turn is prompt-only and carries tagged excerpts of `payments/processor.py` and `tests/test_retry.py` when those regular files are in the snapshot. `command/exec` under the same profile must read the snapshot and must fail sibling, traversal, symlink, home, write, and network probes before the prompt. Approval requests are declined. A cancel sends `turn/interrupt` and then stops the process. The CLI bounds the HTTP call to five minutes. Legacy `SandboxPolicy.readOnly` has no `readableRoots`, and an earlier probe with that policy read a sibling file, so that attempt did not send a prompt. `readOnly.access` is rejected by codex-cli 0.162.1. A stub completion is labelled `scripted` even when the executable is named `codex`. `live` requires the launched binary's `codex-cli` version, its file digest, that version in the app-server user agent, and outcome `completed`. One such turn completed against a disposable payrepo copy. The reported model was `gpt-6.1-sol`, usage was 14847 input tokens and 526 output tokens, and no dollar cost was reported. Mutation stays unavailable. This is one prompt-only subscription turn, not general Codex compatibility. Its limitation is `prompt-only; agent tools disabled; tagged excerpts only`.
- Feature and refactor verification contracts, still unreleased. Product version stays `0.1.0`. Task types are `repair`, `feature`, and `refactor`. Interaction modes stay `agent`, `ask`, and `plan`. `risk_level` is unchanged. `agt fix` remains a repair and rejects a contract. Ask and plan stay read-only, finish `answered`, and do not run baseline or repair verification. `agt feature`, `agt refactor`, `/feature`, and `/refactor` submit a `verify.v1` contract through the existing run path. The client may read `--contract-file`. The API accepts the object and does not open a client path. Empty checks, escaping paths, profile mismatches, and a contract on repair, ask, or plan are rejected. The daemon stores the validated contract and its digest. Model output and run-copy edits cannot replace it. Protected check paths are denied. Changing the checks is a new run and a fresh baseline. Feature success is outcome `feature_implemented`: regression passed before the edit, acceptance failed for a real test reason before the edit and passed after it, and regression still passes. `already_satisfied` means acceptance already passed and is not a newly implemented feature. `verification_infrastructure` covers a missing executable, a timeout, an empty run, and an import error. Refactor success is `checks_passed`: the same protected checks passed before and after the edit. That outcome does not claim proof of behavioral equivalence. `refactor_baseline_failed` is not a verified refactor. The verdict is the verifier execution, not the model text. Migration `008_verify.sql` adds the task, contract, baseline, final evidence, outcome, and verification digest. Older rows default to `repair` with an empty contract. The verification digest is bound to the patch artifact. Apply still refuses a wrong artifact digest, a mismatched verification digest, and a stale source file, and writes nothing in those cases. Approval still requires the argument hash and does not revise the contract. Codex stays prompt-only. This milestone does not enable Codex file tools or Claude execution. Fixtures are `eval/fixtures/featuregate` and `eval/fixtures/refactorgate`. `eval/fixtures/payrepo` is unchanged. Scripted provider answers stay outside those trees.

## 0.1.0

Local reviewable beta. Not published. Not an external beta for macOS, Windows, or linux/arm64.

This repository has no `LICENSE` file and is not presented as licensed.

- Fail closed when `AGT_INTEGRATION=1` and Postgres, Docker, or a sandbox image is missing. `make unit` stays dependency-free. `scripts/test.ps1` is the PowerShell entry and was not executed here.
- Score 20 scripted fake-provider repairs across Python, Go, and JavaScript, including a recovery, an approved test-file edit that passes the in-repo test and fails a hidden check, and an honest verification failure. This is not a hosted-model evaluation.
- `scripts/package.sh` writes unsigned `agt` and `agtd` archives, checksums, and `dist/BUILD.txt`. linux/amd64 is executed only as `agt version`. The other archives are cross-compiled and were not executed.

The earlier milestones on this line of work added loopback auth, explicit Python/Go/JavaScript profiles, a persisted repair transcript, a digest-bound local apply, job leases, and daemon discovery. A hosted model was not called. Applying a patch remains explicit. A cost budget is not a hard dollar cap when prices are zero or usage is unreported. Tool execution is not exactly-once.
