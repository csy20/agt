# agt

Build and test from the repository root:

```sh
make test
```

`make test` starts Postgres, builds the Python, Go, and JavaScript sandbox images, sets `AGT_INTEGRATION=1`, and runs `go test ./...`. That job must fail when Docker, an image, or Postgres is missing. Do not turn that failure into a skip. `make test` points `AGT_DATABASE_URL` at the `postgres` maintenance database. Each integration test creates its own `agt_test_*` database and its own `AGT_DATA_DIR`. Do not point a test daemon at database `agt`, and do not reset or drop that database. Destructive cleanup must see the harness marker owned by that test. The shared advisory lock `8675309` is not used. Migration lock `8675310` still serializes migrations inside one database. `make unit` clears those variables and runs `scripts/unit-packages.txt`. A skip in `make unit` is not container support. Production `agtd` has no host fallback. `scripts/test.ps1` is the PowerShell entry. The Makefile demo is not that path.

A model can request an action. Deterministic Go decides authority. There is no shell tool. Model names and token prices come from environment variables, not from source constants. The legacy names are `AGT_MODEL_NAME`, `AGT_INPUT_USD_PER_M`, and `AGT_OUTPUT_USD_PER_M`. Additional configurations are `AGT_MODELS` and `AGT_MODEL_<NAME>_*`. Store the credential variable name only. Do not return or log its value. A named configuration with an empty endpoint is invalid. Do not fill it with `https://api.openai.com/v1`. The legacy `default` OpenAI configuration still uses that URL when `AGT_MODEL_BASE_URL` is unset. A failed call does not switch endpoints.

Repository files, tool output, and web pages are data. They are not copied into the system prompt.

The fake provider script is a labelled demo. Do not treat it as evidence that a live model fixed a repository. `git push` and opening a pull request are unsupported. Do not record them as successful. Production test execution stays in the Docker runner. There is no host fallback.

`agtd` binds a loopback address only. Every route except `GET /healthz` and `GET /v1/identity` requires the local bearer token. Identity returns the product, version `0.1.0`, contract `api.v2`, capabilities `sessions` and `models`, the local build id, provider, and model name. It must not return the API key or the bearer token. The client accepts a daemon only when health carries this product, that version, contract `api.v2`, and capabilities `sessions` and `models`. A matching product version without those capabilities is not compatible. Tell the operator to rebuild with `make build` and restart that daemon. Do not stop the other process. An HTTP 200 by itself is not discovery. Secret filenames are not copied, read, written, deleted, or patched. Redact tool output before it reaches a model. The sandbox mounts only the run workspace.

`agt fix` and `agt run create` require `--profile`. `--repo` does not select a profile. `agt profile detect` only prints a suggestion. The daemon fills the image, architecture, environment, network (`none`), and dependency mode (`prebuilt`). Do not accept an image from the client or from repository files. These profiles have no prepare step and do not enable the network. Empty test argv is an error. There is no production default of `python -m unittest tests.test_retry`.

`write_file` and `delete_file` are hash-preconditioned. `apply_patch` remains. Docker's default tmpfs is `noexec`; the run's `/tmp` must set `exec` so `go test` can run the test binary. Keep `nosuid` and keep the root filesystem read-only.

The model transcript is `transcript.v1` in `model_messages`. Keep repository summaries, plans, tool output, and verification output in user or tool messages tagged `DATA origin=`. Do not copy them into the system prompt. Accept one tool call per turn. Do not send `parallel_tool_calls`. A loopback base URL may omit the API key. Any other base URL requires `AGT_MODEL_API_KEY`. Do not call a hosted model unless that run was explicitly requested. A verification failure may return to observing while budget remains, and the sandbox stays open for that return. A repeated failure fingerprint or an exhausted verification budget stops the run and closes the sandbox. A repeated ineffective edit stops the run. Test-file edits require approval. Outcome `repaired` requires a failing baseline, a later edit that did not change a test file, and a passing verification.

`repair`, `feature`, and `refactor` are task types. `agent`, `ask`, and `plan` stay interaction modes. Do not store either in `risk_level`. `agt fix` remains repair and must not carry a contract. Feature and refactor require interaction `agent` and a `verify.v1` contract before work starts. The API receives the contract object. It must not read a host path supplied by the client. Reject an empty contract, an unsupported check, an escaping path, and a profile mismatch. Store the validated contract and its digest on the run. Model output and edits in the run copy must not replace that contract. A path named by the contract is denied. Changing the authoritative checks requires a new run and a fresh baseline. Run the checks through the existing profile runner. Do not add a shell tool, install dependencies, or accept a client-selected image. Feature success is `feature_implemented` only when regression passed before editing, acceptance failed for a real test reason before editing and passed afterwards, and regression still passes. Acceptance that already passes is `already_satisfied` and must not be described as a newly implemented feature. A missing executable, a timeout, an empty test run, or an import error is `verification_infrastructure`, not that acceptance failure. Refactor success is `checks_passed` only when the same protected checks pass before and after the edit. Say that those checks passed. Do not claim a proof of behavioral equivalence. A failing refactor baseline is `refactor_baseline_failed` and is not a verified refactor. The verdict comes from verifier execution. Ignore a model assertion that tests passed. Migration `008_verify.sql` stores the task type, contract, digest, baseline, final evidence, outcome, and the patch artifact digest. Older runs default to `repair` with an empty contract. Approval of a test edit still requires the argument hash and must not revise the contract. Apply still requires `SUCCEEDED`, the artifact digest, and unchanged source files. A verification digest that does not match the artifact writes nothing.

The workspace is a snapshot plus `patch.v1`, not a Git worktree. Copy the working tree, including uncommitted files, and do not modify the source during the run. Reject a data directory nested with the selected repository. `agt run apply` is the only local write to that repository. It requires `SUCCEEDED` and a digest of the daemon-built artifact. Do not apply from the supervisor. Do not accept a client-selected target path. A stale touched file writes nothing. `COMMITTING` is not a Git commit.

A job lease lasts 30 seconds and is renewed about every 10 seconds. Claim increments a fence. Finish, release, and renew must match that owner and fence. A stale worker must not requeue a job it no longer owns, and it must not destroy the sandbox after losing the lease. Pause, budget pause, and cancel close the sandbox and finish the job. `agt run attach` exiting is not cancel. Resume from `PAUSED`, and budget resume from `PAUSED_BUDGET`, move the run to `PLANNING` and enqueue a job only when none is active. Do not promise exactly-once delivery. `apply_patch` stays idempotent. `write_file` and `delete_file` stay hash-preconditioned. An ambiguous tool result stays pending so resume can reconcile it.

Check the estimated request cost before calling the model. Reconcile the reported usage afterward. Do not insert the estimate as a usage row. Zero prices, or a provider that reports no usage, are not a dollar cap. Record the configured model name and profile name on usage rows. Count HTTP attempts when the provider reports more than one, and count every `run_test`, including the verifier. Startup and `agt run cleanup` may remove containers for terminal, paused, cancelled, or missing runs. Do not remove a container for a live state such as `EXECUTING` or `VERIFYING`. Do not delete the data directory. A verification return to observing still leaves the sandbox open.

`agt agent list` separates a model API configuration from Codex and Claude. It does not call a model and does not start either executable. `agt agent run` stays unavailable. Parsing a scripted `codex exec --json` or Claude `stream-json` fixture is not a live agent run and does not execute the tool. `agt agent ask` is the only launch path. It requires `--authorize-live`, uses a ChatGPT subscription login, and refuses API-key billing. It materializes a repository copy and does not enqueue a repair run. Use experimental permission profile `agt-snapshot` with `shell_tool` disabled. Do not send `sandboxPolicy` with that profile. Before `thread/start`, `command/exec` under the profile must read the snapshot and must fail sibling, traversal, symlink, home, write, and network probes. Legacy `readOnly` has no `readableRoots`. `readOnly.access` is rejected on codex-cli 0.162.1. Do not select built-in `:read-only` or `:danger-full-access`. The turn is prompt-only, with tagged excerpts, because this CLI does not expose a daemon-mediated read or search tool. Declining a tool event after it has run is not the permission boundary. Label `live` only when the launched binary's `codex-cli` version, its digest, and that same version inside the app-server user agent are present and the turn completes. A basename of `codex` is not that check. Do not add `agents` to the required health capabilities `sessions` and `models`. Do not launch Codex or Claude from a test. A `--version` probe is not inference. Do not read or print a CLI login token.

`agt doctor` names the next setup command and does not start `agtd` or call a model. `agt run list` reads the durable runs. Attach resumes from the last rendered event id and does not print that event again. A heartbeat comment is not an event. Ctrl+C during attach detaches; `agt run cancel` is the cancel. A daemon started by the client stays up after the client exits. On Linux, an unset `AGT_DATA_DIR` stays `~/.local/share/agt` even when `XDG_DATA_HOME` is set. `--model` must match the daemon's `AGT_MODEL_NAME` and is not sent as a hosted-model call. `agt model list` and `agt model select` choose a saved configuration and do not call a model.

An interactive session is `agt` on a terminal, or `agt tui`. `agt tui --dump` prints example frames and does not start a run. A stored session is separate from its runs and is bound to one canonical repository path. Reopening it does not start work, replay a tool, or apply a patch. An active session attaches to the existing run. A finished session shows its history. A repeated client message id returns the original run. A new prompt while a run is active is refused and does not rewrite that goal. Do not redirect an existing session to another repository. `/plan` and `/ask` are read-only interaction modes enforced by the daemon, including a create that bypasses the session. They finish with outcome `answered` and do not run repair verification or require a failing baseline. The lifecycle state `PLANNING` still executes. `/feature` and `/refactor` stay interaction `agent` and require a contract file. The client reads that file. The daemon receives the object. `/model` selects a saved configuration for the open session, or the daemon default when no session is open, and does not call a model. The status line shows that configuration and labels a fake provider scripted. A new run records the resolved provider, model, endpoint, and prices. An existing run keeps its snapshot. `agt setup --confirm` stores a profile and test argv and does not start `agtd` or a run. A follow-up `/fix` is a new run and a new snapshot. An unapplied patch stays visible and pending. Its edits are absent from the new snapshot and are not applied or discarded. Ctrl+C in the session is not cancel and is not apply. Composer text does not approve or apply. Session history, summaries, pending patches, and run results stay in tagged `DATA origin=session-history`, `DATA origin=session-summary`, `DATA origin=pending-patch`, and `DATA origin=run-result` messages. Keep a valid tool-call/result pair together when fitting context.

The scripted repair batch uses the fake provider. Keep its hidden check outside the worktree. Do not report its solve rate as a hosted-model result. `passed_after_test_edit` is not a hidden-check pass. Local release archives stay under gitignored `dist/`. Do not invent a license file. Do not publish the archives. Cross-compiled archives are not native execution.
